# ADR-001: Modular Microservice Backend with Separated AI/CV Service

## Status
Accepted

## Context
FitFlow needs fast delivery from a mid-sized team, strong real-time social features, and an
AI/computer-vision capability that is best served by Python's machine learning ecosystem.

## Decision
Keep the core backend in Node.js/Express as focused microservices:
- Workout & User Service
- Social Service
- Nutrition Service
- Notification Service

Isolate AI personalization and computer-vision nutrition logging into a separate **FastAPI
(Python) microservice**, called from the Node.js services over REST/gRPC.

## Consequences

**Positive:**
- Team stays productive in one primary language (JavaScript/TypeScript) for most services.
- The AI/CV service can use best-in-class ML tooling (TensorFlow, PyTorch, ML Kit) and can be
  scaled or deployed independently of the rest of the backend.

**Negative:**
- Introduces one additional language and deployment unit to operate.
- Requires clear, versioned API contracts between the Node.js services and the AI/CV service.

## Alternatives Considered
- **Single Python monolith** — rejected: slower for real-time/social features, less team
  familiarity with Python for general backend work.
- **Building AI logic directly in Node.js** — rejected: weaker ML tooling and library support
  compared to Python's ecosystem.
